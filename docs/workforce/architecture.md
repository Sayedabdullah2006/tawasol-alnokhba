# هيكل منظومة موظفي تواصل النخبة

## القرار الملزم من المستخدم

تُبنى الهيكلية أولًا قبل توسيع الوظائف. بوابة الموظف مستقلة عن لوحة العميل، ولها داشبورد رئيسية وقائمة هرمية: أقسام رئيسية ← صفحات فرعية ← تفاصيل السجل. الطلبات مركز شامل وليست تعديل بيانات فقط. يبقى تنفيذ الموديولات واختبار الواجهات لكل دور مطلوبًا بعد تثبيت الهيكل.

## حدود المساحات والأدوار

| المساحة | المسار | المستخدم | نطاقها |
|---|---|---|---|
| بوابة الموظف | `/employee` | موظف نشط | عمله وملفه وأهدافه ومستحقاته وطلباته والمشترك معه صراحة |
| إدارة فريق العمل | `/admin/workforce` | مدير النظام الحالي | إدارة الموظفين والتكليف والمراجعة والاعتماد والسياسات والتقارير |
| لوحة العميل الحالية | `/dashboard` | العميل، والمدير حيث يسمح النظام الحالي | طلبات النشر والعضويات وخدمات العميل |

قائمة الموظف وترويسته وتذييله مستقلة؛ لا تظهر فيها عضوية العميل أو طلبات النشر أو مسار المخترع. فصل الواجهات لا يغني عن حراس الخادم وRLS والتخزين. لا ينشأ دور ثالث للإدارة الداخلية.

## خريطة بوابة الموظف

المصدر المركزي للمسارات والعناوين والارتباطات: `src/lib/workforce/navigation.ts`.

| القسم الرئيسي | الصفحات الفرعية | المسار الأساسي |
|---|---|---|
| الرئيسية | الملخص الشخصي، الأرقام، التنبيهات، آخر القرارات، الوصول السريع | `/employee` |
| العمل والإنجاز | مهامي، مشاريعي، تقويم العمل، سجل وقت العمل | `/employee/work` |
| الأهداف والأداء | أهدافي، تقييمي وخطة التطوير | `/employee/performance` |
| المستحقات المالية | ملخص مستحقاتي، كشوف الرواتب، الراتب والبدلات المتفق عليها، العمولات والمكافآت، السلف والالتزامات، بيانات الصرف | `/employee/finance` |
| الحضور والإجازات | حضوري وانصرافي، جدول دوامي، أرصدة الإجازات | `/employee/attendance` |
| الطلبات والموافقات | كل طلباتي، وأنواع الطلبات أدناه | `/employee/requests` |
| ملفي الوظيفي | بيانات العمل والتواصل، مستنداتي، عهدي، التهيئة وتسليم العمل، سياسات الشركة | `/employee/profile` |
| الإشعارات | مركز الإشعارات، تفضيلات التنبيهات | `/employee/notifications` |

أنواع الطلبات: إجازة؛ استئذان؛ عمل عن بعد؛ تعويض أو استرداد مصروف؛ سلفة؛ تصحيح حضور؛ خطاب أو شهادة؛ تعديل بيانات؛ استفسار أو اعتراض مالي؛ مراجعة تقييم؛ طلب إداري آخر. نوع «آخر» لا يسمح بتجاوز دورة الموافقة المتخصصة أو إنشاء أثر مالي تلقائي.

تظهر الأقسام في قائمة قابلة للفتح والإغلاق؛ يفتح القسم الحالي تلقائيًا ويتميز رابط الصفحة الحالية. في الجوال تُفتح القائمة من «أقسام البوابة». نظرة كل قسم تعرض صفحاته، وصفحة كل وظيفة تعرض الروابط إلى الصفحات ذات الصلة. صفحة التفاصيل لاحقًا تستخدم معرف السجل الحقيقي تحت الموديول، ولا تصبح عنصرًا دائمًا جديدًا بالقائمة.

## هيكل لوحة المدير المقابل

جميع الأقسام التالية ضمن لوحة المدير الحالية، دون إنشاء إدارة مستقلة بحسابات جديدة:

| قسم الإدارة | الصفحات | مقابل الموظف |
|---|---|---|
| نظرة عامة | المتأخرات والعوائق والموافقات والأهداف والتكاليف والمستحقات | ملخص شخصي فقط |
| الموظفون | الدليل، الأقسام، الملف، العقود، المستندات، العهد، التهيئة والمغادرة | ملفي الوظيفي |
| إدارة العمل | اللوحات والمهام، المشاريع والمراحل، القوالب والتكرار، التسليمات، توزيع العبء | العمل والإنجاز |
| الأهداف والأداء | أهداف الشركة والأقسام والموظفين، اعتماد النتائج، التقييم والتطوير | أهدافي وتقييمي |
| المالية | تعويضات الموظفين، سياسات العمولات، الاستحقاقات، مسيرات الرواتب، الدفعات، السلف والتسويات | مستحقاتي |
| الحضور والإجازات | الجداول، سجلات الحضور، السياسات والأرصدة | حضوري وأرصدتي |
| الموافقات | صندوق موحد، تفاصيل الطلب، القرار، الأثر، السجل | طلباتي وقراراتها |
| التقارير والإعدادات | تقارير قابلة للتتبع، صلاحيات المشاركة، السياسات ذات الإصدار، الأتمتة والإشعارات | التفضيلات والسياسات المسموحة فقط |

لا تُنشأ نسختان من نفس البيانات: صفحة المدير وصفحة الموظف تستخدمان السجل نفسه بصلاحيات مختلفة. صندوق الموافقات فهرس موحد للعمليات؛ يُنفذ الاعتماد في الموديول المالك للأثر.

## العلاقات ومصدر الحقيقة

| الأصل | علاقاته | ضابط مهم |
|---|---|---|
| الموظف | حساب، قسم، تعاقد، بيانات صرف، مستندات، مهام، أهداف، حضور، طلبات، مستحقات | التعليق يمنع الدخول ويحفظ التاريخ؛ نقل المسؤوليات إجراء مستقل موثق |
| المشروع | أعضاء، مراحل، مهام، ملفات، تسليم مسؤولية | عضوية المشروع لا تعني رؤية رواتب أعضائه أو بيانات العميل كاملة |
| المهمة | لوحة وحالة، مسؤول، مشاركون، قائمة تحقق، تعليقات، ملفات، وقت، اعتماديات وتسليم | المشروع والهدف والعميل وطلب النشر روابط اختيارية؛ المهمة المستقلة حالة أصلية |
| الهدف | فترة ووحدة ومستهدف ووزن، نتائج وأدلة واعتماد | النتيجة تُحسب من مصدر معروف؛ المصدر نفسه لا يُحتسب مرتين |
| العمولة/المكافأة | سياسة بإصدار، مصدر، توزيع بين الموظفين، اعتماد، سطر راتب/دفعة | تعديل السياسة لا يغيّر التاريخ؛ الاسترداد ينشئ تسوية للمراجعة |
| كشف الراتب | فترة، بنود، استحقاقات معتمدة، حسميات معتمدة، دفعات واعتراضات | فصل المتوقع عن المعتمد والمصروف؛ الفترة المغلقة لا تُعدل مباشرة |
| طلب الإجازة | الموظف، النوع، الفترة، قرار، دفتر حركة الرصيد، تسليم العمل | أثر الرصيد بمعاملة واحدة ومنع التكرار؛ الإلغاء يعكس الأثر الموافق عليه |
| طلب التعويض/المصروف | مبلغ وعملة ومرفقات، مشروع اختياري، قرار، مستحق، دفعة | الموافقة ليست إثبات صرف؛ لا يدخل الصافي مرتين |
| طلب السلفة | مبلغ، قرار، سلفة معتمدة، خطة أقساط | الطلب ليس السلفة المصروفة؛ الأقساط ترتبط بالمسير الصحيح |
| تصحيح الحضور | سجل أصلي، تعديل مقترح، سبب، قرار | لا يكتب الموظف فوق السجل الأصلي؛ تاريخ التدقيق محفوظ |
| طلب خطاب | نوع وغرض وجهة، قرار، مستند نهائي | المستند الناتج يظهر في مستندات الموظف بصلاحية تنزيل مستقلة |
| طلب تعديل البيانات | الحقل والقيمة والسبب والقرار | لا تتحول القيمة إلى أصل معتمد قبل الموافقة |
| الإشعار | حدث، مستلم، رابط للمورد، حالة قراءة | لا ينسخ بيانات حساسة إلى عنوان الإشعار؛ صلاحية المورد تُفحص عند فتحه |

تتبع المهمة: تكليف ← تنفيذ ← تسليم ← مراجعة ← تعديل أو اعتماد. تتبع الطلب: مسودة ← إرسال ← انتظار قرار ← اعتماد أو رفض ← تنفيذ أثر عند الحاجة ← إغلاق. الإلغاء لا يعكس الأثر تلقائيًا دون ضوابط النوع. مسير الراتب: إعداد ← مراجعة ← اعتماد ← إثبات صرف جزئي/كامل ← إغلاق.

## الداشبورد الرئيسية

| البطاقة المخططة | مصدرها | وجهة فتح التفاصيل |
|---|---|---|
| مهام اليوم والمتأخر والعوائق | المهام المصرح بها وحالاتها ومواعيدها | مهامي بفلاتر مطابقة |
| تقدم المشاريع | مراحل ومهام المشاريع المشتركة بطريقة معلنة | مشاريعي |
| تقدم الأهداف | النتائج المعتمدة للفترة | أهدافي |
| المستحقات غير المصروفة | الاستحقاقات المعتمدة ناقص الدفعات المسجلة | ملخص مستحقاتي |
| الحضور ورصيد الإجازات | الجداول والسجلات ودفتر الأرصدة | الحضور أو الأرصدة |
| الطلبات المعلقة وآخر القرارات | الطلبات حسب النوع والمالك | كل طلباتي أو تفاصيل الطلب |
| المستندات والعقد القريب من الانتهاء | التواريخ المسجلة وصلاحية الاطلاع | المستندات أو الملف |
| التنبيهات | الأحداث المصرح بها وتفضيلات التنبيه | المورد الذي يتطلب الإجراء |

كل رقم يذكر الفترة والمعنى، ويقود إلى البيانات التي تكوّنه. البيانات غير المتوفرة لا تعرض صفرًا يوحي بقياس فعلي. الأرقام الحالية في الرئيسية تخص موديول الملف الوظيفي فقط، ومصدرها استعلامات فعلية؛ الملخص الشامل يتوسع عند اكتمال الموديولات.

## التنفيذ المرحلي الحالي

- متاح فعليًا: الملف والتواصل، المستندات، تعديل البيانات، بيانات الصرف، مؤشرات الملف وقراراته.
- بُنيت هيكلية قابلة للتصفح لبقية الصفحات مع تنبيه صريح «معاينة الهيكلية». ليست موديولات مكتملة، ولا تنشئ معاملات وهمية.
- الروابط السابقة للمستندات وبيانات الصرف تعاد إلى مساراتها الهرمية. `/employee/requests` صار مركز القسم، وتعديل البيانات تحت `/employee/requests/profile-change`.
- لم تضف هذه الهيكلية جداول أو عمليات على الإنتاج. اختبارات واجهتها والتنقل لا تعد قبولًا لوظائف المهام أو المالية أو الإجازات.
- يحافظ `requirements.md` على النطاق الكامل، وتتابع `implementation.md` و`quality.md` تنفيذ الموديولات وقبولها.

## اختبار الهيكلية قبل استكمال الموديولات

فتح الرئيسية بحساب موظف؛ فحص غياب قوائم العميل؛ فتح الأقسام الرئيسية وصفحاتها الفرعية والروابط المرتبطة؛ التأكد من فصل نوع تعديل البيانات عن مركز الطلبات العام؛ التحقق من القوائم على الجوال والكمبيوتر؛ استمرار الصفحات الفعلية؛ منع حساب العميل/الموظف المعلق من الوصول؛ فحص كل مسار مسجل وكل رابط مرتبط؛ البناء والأنواع.
