اعتمد هذا التحديث لعرض حالات تواصل النخبة كما هي في أول سعودي. لم تتغير حالات الطلب أو الدفع أو انتقالاتها، ولم يُضَف محرك حالات جديد؛ الإضافة قراءة وعرض عبر API فقط.

1. GET catalog أصبح يعيد status_definitions:
- request: جميع تسميات حالات الطلب الـ19 وأوصافها وألوانها من CLIENT_STATUS_LABELS في تواصل النخبة، بنفس النصوص الموجهة للعميل.
- payment: تسميات حالات الدفع، ومنها pending وpaid وrefund_pending وpartially_refunded وrefunded، مع دعم القيم القديمة unpaid وfailed إن كانت مسجلة.
- checkout: تسميات حالة جلسة الدفع؛ تختلف عن حالة سداد الطلب.
- progress_steps: تعريف المراحل الحالي في تواصل النخبة. هذا تعريف عرض وليس سجل أحداث أو إثبات اكتمال مرحلة.
- version: بصمة تعريفات الحالات. احترم مدة كاش catalog الحالية، ولا تثبت نسخة من القاموس في الكود.

2. GET orders وGET orders/{id} يحتفظان بجميع الحقول السابقة، ومنها status وpayment_status دون إعادة تسمية الرموز أو استبدالها، ويضيفان:
- status_info: {code, known, label, description, color}
- payment_info: {code, known, label, description, color, is_paid, has_confirmed_payment}
- financial_review: {required, label, message}
- checkout_state: حالة آخر جلسة دفع محفوظة وتواريخها وعلم expired، أو null.
- refresh_after_seconds: 15 أو 60 للتحديث الدوري، و0 عند انتهاء المتابعة التلقائية. حدّث أيضًا عند الرجوع للصفحة وبعد الإجراء الناجح.
- provider_attempt_status_available: false حاليًا؛ تفاصيل فشل آخر محاولة لدى البوابة لا تُحفظ في سجل الطلب الحالي. لا تخترع نتيجة محاولة أو تعتبرها pending أو paid.

3. أُضيف مسار خفيف للتحديث:
GET https://nukhba.media/api/partners/v1/orders/{id}/state
يستخدم توقيع HMAC وهوية الشريك والعميل الحالية، ويعيد JSON بالصيغة المعتادة {data,trace_id}. data تحتوي id وstatus وpayment_status وpaid_at وupdated_at وrefund_amount وrefund_timing وcontent_sent_at وcontent_approved_at والحقول الجديدة أعلاه. refund_amount بالهللة.

استخدمه لاستطلاع الحالة. إذا تغيرت الحالة أو updated_at أو بيانات المراجعة المالية، أعد جلب تفاصيل الطلب الكاملة لتحديث المحتوى والأزرار والمرفقات. لا تعتمد على هذا المسار وحده لتحميل التصاميم أو content_revision.

4. اعرض status_info.label ووصفها بدل statusName المحلي، وpayment_info.label بدل paymentName المحلي، في بطاقات الطلبات وتفاصيل الطلب وصفحة العودة. أبقِ الحالتين مستقلتين، ولا تحوّل approved+paid إلى حالة طلب مختلقة. اللون القادم دلالي؛ طبّقه من خريطة CSS آمنة بهوية أول سعودي، لا تنفذ أسماء فئات أو HTML غير موثوقة.

5. إذا financial_review.required=true فاعرض رسالة المراجعة المالية بجوار حالة الدفع الأصلية، ووضّح عدم تكرار الدفع. قد يكون الطلب مدفوعًا وتوجد دفعة إضافية تحتاج مراجعة؛ لا تستبدل paid بـreview_required، ولا تخلطها مع request.status=payment_review الخاصة بالتحقق من إيصال الدفع.

6. partially_refunded يعني «تم استرجاع جزء من المبلغ»، وليس «لم يؤكد السداد». اعرض refund_amount وrefund_timing كما تصدر مركزيًا. لا تجعل الاسترداد الجزئي أو المجدول للنشر اكتمال تنفيذ. انتهاء جلسة دفع ليس فشل سداد مؤكدًا، ووجود paid_at لا يغيّر النص الخام للحالة.

7. استمر بالتحديث عند refresh_after_seconds>0 حتى لو كان status=completed وتوجد مراجعة مالية أو استرداد قيد المعالجة. القيمة 0 توقف الاستطلاع الدوري فقط؛ تبقى العودة للصفحة والتحديث اليدوي فعالتين. أخطاء STATE_UNAVAILABLE تعني تعذر القراءة مؤقتًا؛ احتفظ بآخر بيانات مع تنبيه واضح وأعد المحاولة، ولا تستبدل الحالة بحالة نجاح أو فشل.

8. إذا known=false فاحتفظ بالرمز الخام واعرض التسمية الاحتياطية القادمة من الخادم. لا تعتبر الحالة الجديدة مكتملة أو مدفوعة ولا تفتح إجراءً حساسًا بناءً عليها.

اختبر جميع تعريفات الطلب الـ19، وحالات الدفع السبع، والمراجعة المالية المنفصلة، والاسترداد الجزئي، وطلب مكتمل مع استرداد قيد المعالجة، والرموز غير المعروفة، وتطابق الحالة بين القائمة والتفاصيل وstate، وصلاحيات عميلين. استخدم محاكاة معزولة للانتقالات؛ لا تغير حالات طلبات العملاء الفعلية للاختبار.

لا تغير الربط أو الدفع أو إصدار الفواتير أو حالات تواصل النخبة. المطلوب انعكاس البيانات الحالية هناك بدقة في واجهة أول سعودي. لا تعلن دعم فشل آخر محاولة دفع أو سجل انتقالات تاريخي كامل؛ هذه البيانات ليست ضمن العقد الحالي.
