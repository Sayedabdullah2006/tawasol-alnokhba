أُضيف مسار تحميل الفاتورة المركزية إلى API تواصل النخبة:
GET https://nukhba.media/api/partners/v1/orders/{id}/invoice

استخدم HMAC والمفاتيح وهوية الشريك الحالية، وX-Customer-ID من جلسة العميل الموثقة في خادم أول سعودي. لا يحتاج العميل حسابًا أو جلسة في تواصل النخبة.

النجاح 200 يعيد PDF ثنائيًا مباشرةً، وليس JSON أو data أو رابطًا عامًا. Content-Type: application/pdf، وContent-Disposition يحمل اسم الملف، وX-Trace-ID للتتبع، وCache-Control: private, no-store, max-age=0.

في client.mjs المحدث:
const invoice = await api(`orders/${orderId}/invoice`, { customerId, responseType: 'pdf' })
// invoice.bytes: Uint8Array، invoice.filename، invoice.contentType

أضف مسار تنزيل داخلي في خادم أول سعودي يتحقق من الجلسة، ويستدعي المسار الموقّع، ويعيد bytes كـPDF مع اسم ملف آمن وprivate, no-store وnosniff. استعمله لزر «تحميل الفاتورة» في طلباتي وتفاصيل الطلب. لا تجعل استجابة الفاتورة قابلة للتخزين في CDN، ولا تكشف مفاتيح التوقيع في المتصفح.

الأخطاء بصيغة JSON المعتادة { error: { code }, trace_id }:
- 401: التوقيع أو المصادقة غير صالحين.
- 404 ORDER_NOT_FOUND: الطلب غير موجود أو لا يخص الشريك والعميل الحاليين.
- 409 INVOICE_NOT_AVAILABLE: لم يتأكد الدفع أو ليس للطلب مبلغ موجب. أخفِ/عطّل التنزيل قبل تأكيد الدفع مع توضيح السبب؛ الخادم يتحقق دائمًا.
- 409 REPLAY_REJECTED: استخدم nonce جديدًا لكل محاولة.
- 503 INVOICE_UNAVAILABLE: تعذر تجهيز المستند مؤقتًا؛ اسمح بإعادة المحاولة دون عرض خطأ داخلي.

الفاتورة هي فاتورة الخدمة المركزية الأصلية لشركة تواصل النخبة، بنفس رقمها وبياناتها. لا تنشئ فاتورة أو ترقيمًا موازيًا ولا تبدّل هوية البائع في PDF. الطلب المدفوع المسترد يحتفظ بفواتيره الأصلية؛ هذا المسار ليس إصدار إشعار دائن.

اختبر: عميل الطلب المدفوع ينزّل PDF، عميل آخر لا يستطيع، الطلب غير المدفوع لا يتيح التنزيل، التكرار يعيد المستند المركزي نفسه، والفشل المؤقت قابل لإعادة المحاولة. استخدم بيانات اختبار معزولة دون خصم فعلي أو إصدار فاتورة مالية تجريبية على الإنتاج. بقية الربط والدفع والكتالوج دون تغيير.
