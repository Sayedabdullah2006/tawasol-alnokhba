- أُنشئت إعدادات محلية في `.env.local` مع أسرار عشوائية؛ لم تُطبع أو توضع في مستندات الربط أو Git.

## الباقات والتوافق

الأسعار الأساسية الحالية لأنواع الأخبار لم تتغير. الباقات الجديدة v2_basic/v2_reach/v2_presence/v2_elite/v2_career تستخدم الزيادات 0/400/1400/2800 وسعرًا مستقلًا 1799 للحضور المهني. الإعلان 250/500/200 مشمول حسب الباقة، ولا يدخل أساس الخصم. السياسة الضريبية البرمجية الحالية بقيت دون إضافة ضريبة جديدة؛ هذه ليست إفادة بالإعفاء الضريبي.

المعرّفات القديمة basic/pro/elite/prime ومعاملاتها محفوظة. الحملات متعددة الأخبار تبقى على مسارها الحالي؛ العضويات والجهات و«أخرى» ليست ضمن API الشريك v1. الطلب الجديد يحفظ package_snapshot، وتعرضه الإدارة والعميل بدل إعادة اشتقاق محتواه من كتالوج قابل للتغيير.

لم تُحذف سياسات الصلاحيات القديمة. أُضيفت سياسات restrictive تحصر قراءة الطلبات الجديدة في صاحب الطلب أو الإدارة، وتحصر الكتابة المباشرة في الإدارة والخادم، وتحمي طلبات الشريك التي لا ترتبط بحساب محلي. إجراءات المحتوى للعميل تنفذ على الخادم بعد التحقق من الملكية والحالة.

## التحقق المنفذ

1. `npm run build`: نجح البناء الإنتاجي الكامل، بما فيه TypeScript وتوليد الصفحات. أُخرج مجلد `outputs/**` المولد من نطاق فحص التطبيق؛ كان يحتوي نسخة مرجعية قديمة تستورد ملف .ts مباشرة.
2. `npx tsc --noEmit --pretty false`: نجح.
3. `node scripts/payment-access-test.mjs`: نجحت 9 حالات لملكية الدفع، بينها دفعات تاريخية بلا metadata مرتبطة مسبقًا بمعرّف المزود. لا يُقبل معرّف طلب يرسله العميل وحده كدليل ربط.

3. ESLint للملفات الجديدة في نطاق الباقات والربط والدفع: نجح.
4. `node scripts/partner-api-test.mjs`: نجحت 40 عملية HTTP عبر المعالجات الفعلية، مع قاعدة البيانات والتخزين الفعليين، وفحوص إضافية للتسعير والتوازي والمدفوعات وSDK.
5. `node scripts/partner-browser-test.mjs`: نجح تشغيل Next محليًا والاتصال HTTP الفعلي، وتبادل صلاحية جلسة الدفع بCookie، وإظهار نموذج ميسر التجريبي، وصفحة الأسعار، وتسجيل جلسة عميل SSR ونموذج الحضور المهني. فُحصت أحجام 1440/768/390 دون تجاوز أفقي للدفع.
6. فحص وصول فعلي بحساب عميل مؤقت: يرى طلبه الجديد، ولا يستطيع تغيير final_total مباشرة أو قراءة طلب الشريك من Data API. فحص anon منع الوصول لجداول الربط.
7. جرت مقارنة عينة ثابتة من الطلبات التاريخية قبل الاختبار وبعده؛ الأسعار والحالات ومعرّفات الباقات بقيت كما هي. الترحيل نفسه لا يحتوي إعادة تسعير للطلبات القديمة.
8. فُحصت ملكية الطلب، والتوقيع الخاطئ، والطابع الزمني القديم، وإعادة nonce، والتزامن عند الإنشاء والدفع، واستهلاك العرض مرة واحدة وانتهاؤه، وحظر الطلب الجديد عند وجود طلب غير مدفوع، والإلغاء، والملف الخاص وحجمه ونوعه، والنسخة الحالية القادمة من post_reviews، واعتماد المحتوى.
9. استقبال webhook اختُبر بصيغة secret_token الرسمية، ورفض السر الخاطئ، وإعادة 503 عند فشل التحقق حتى يعيد المزود الإرسال.
10. راجعنا Supabase security advisors. جداول الربط لا تمنح anon/authenticated وصولًا مباشرًا؛ ملاحظة RLS enabled/no policies متوقعة لجداول service_role فقط. وظائف الربط SECURITY INVOKER، مع search_path ثابت وEXECUTE للخادم فقط. ملاحظات المشروع القديمة الأخرى خارج نطاق هذا التغيير.

## حدود الاختبار

- الاختبارات الآلية تستخدم محاكاة ميسر لحالات التعارض. أضيف إليها اختبار منفصل بعمليتين فعليتين في Moyasar Sandbox: paid وfailed؛ لم يُحصّل مبلغ فعلي ولم يُنفّذ استرداد مالي.
- نموذج ميسر الحقيقي اختُبر بمفتاح publishable تجريبي. الاختبار المنشور حمّل الأصول مباشرة دون اعتراض أو محاكاة شبكة. في الاختبار المحلي السابق: في محطة الاختبار حدثت إعادات اتصال TLS مع CDN؛ أعيد تقديم ملف JavaScript الرسمي نفسه داخل اختبار المتصفح فقط بعد تنزيله بتحقق TLS عادي عبر curl. لا توجد هذه المحاكاة أو تعطيل شهادة في كود التطبيق. أضيف تنسيق محلي منخفض الأولوية للحقول في صفحة الدفع حتى تظل مقروءة إذا تأخر stylesheet الخارجي.
- اختبارات SDK/الدفع لا ترسل بريدًا حقيقيًا ولا تشغّل توليد المحتوى. فُحص استدعاء الإشعار/التنفيذ مرة واحدة بمحاكاة، ونظّفت الاختبارات حساباتها وطلباتها وملفاتها المؤقتة.
- لا يمكن اختبار رحلة العودة داخل أول سعودي قبل أن ينفذ الموقع صفحته ويربط إعداداته. بقي اختبار واجهة أول سعودي وصفحة العودة من مسؤولية تنفيذها هناك قبل إطلاق الشراء للجمهور. بوابة تواصل النخبة الفعلية فُعّلت بعد نجاح اختبار Sandbox المركزي.

## إعداد بيئة النشر

1. انشر الكود مع إبقاء الترحيل المضاف والصلاحيات. لا تعِد كتابة الطلبات القديمة.
2. انقل الإعدادات السرية إلى مدير أسرار خادم تواصل النخبة:
   - `PARTNER_API_CLIENTS_JSON`: مثال البنية في config.example.json، مع سر فعلي عشوائي بدل العبارة التجريبية.
   - `PARTNER_CHECKOUT_SECRET`: سر مستقل عشوائي، 32 حرفًا على الأقل، دون NEXT_PUBLIC.
   - `PARTNER_CHECKOUT_BASE_URL=https://nukhba.media`.
3. هوية الشريك `awwal-saudi`، ومعرف الناشر `a91880b6-2252-4aa7-807d-a53eb734771f` (حساب «أول سعودي» الموجود).
4. عنوان العودة المثبت: `https://first1saudi.net/services/orders/return`؛ لا يقبل من جسم طلب العميل.
5. سلّم أول سعودي partner id وkey id والسر الخاص بهذا الشريك فقط، عبر مدير أسرار مناسب؛ لا تشارك PARTNER_CHECKOUT_SECRET أو مفاتيح ميسر أو Supabase.
6. استخدم إعدادات ميسر الحالية للشركة. تحقق من تطابق بيئة المفتاح العام والسري، وضبط webhook إلى `/api/webhooks/moyasar` والسر المشترك. لا تغير حساب التاجر أو مفاتيحه آليًا.
7. Apple Pay غير مفعل في إعدادات المشروع الحالية؛ لا يعد API بأنه متاح. تمارا والتحويل البنكي يبقيان في المسار المحلي السابق، وcheckout الشريك الجديد لميسر فقط.
8. تم اختبار بوابة تواصل النخبة المنشورة في Sandbox وتفعيل live بعدها. اختبر واجهة أول سعودي بعميلين وإتمام رحلة العودة قبل إطلاق الشراء للجمهور. لطلب جلسات Sandbox لاحقًا غيّر PARTNER_PAYMENT_MODE مركزيًا في بيئة اختبار؛ لا تضع مفاتيح ميسر في أول سعودي.

## المراقبة والاسترداد من التعثر

- كل استجابة API تحمل trace_id؛ لا تسجل السر أو صلاحية checkout أو روابط رفع الملفات.
- جلسة الدفع تستعمل مفتاح منع التكرار وتعيد الجلسة النشطة نفسها. الدفع المؤكد يعالج ذريًا في SQL. الدفعة الزائدة أو الواصلة لطلب تغيرت حالته تُسجل review_required وتظهر في لوحة الطلب للمراجعة المالية، دون تنفيذ الطلب مرتين.
- الاسترداد يستعمل إدارة الاسترداد الحالية وحساب الشركة. لا يملك أول سعودي صلاحية تنفيذ استرداد.
- لتعطيل قناة أول سعودي أزل مفاتيحها من إعدادات الخادم. لا تحذف جداول الطلبات/المدفوعات أو سياسات حماية السجلات الجديدة، ولا ترجع أسعار الطلبات المشتراة إلى أسعار الكتالوج.
- إشعارات التنفيذ والتوليد التلقائي تستخدم آلية المشروع الحالية؛ لا يُقدّم هذا الإصدار نظام مهام خلفية جديدًا أو webhooks صادرة للشريك. تُتابع الحالات عبر API.
